## 一、与原文明确不同的算法机制

### A1. 即时外部奖励与长期优化目标都被替换

原文 p.904 式(20)的即时奖励，是相对“平均算力、平均带宽的伪服务器”的完成时间与能耗改善：

`r_step = alpha * (EFT_ref - EFT_actual)/EFT_ref + (1-alpha) * (Energy_ref-Energy_actual)/Energy_ref`。

p.905 式(25)–(27)的长期目标是工作流完成时间差与能耗，并有工作流任务数及区间平均。

当前 `environment.py:109–121` 直接使用底层公共环境的奖励，定义 `outer_cost = -external_reward`。基类 `environments/irws.py:593–600,744–754` 的实际公式为：

`r_ext = 0.25 * (-0.001 * delta_energy_total) + 0.75 * [-clip(max(0, finish-task_subdeadline)/300, 0, 1)]`。

当前元学习外层同样优化这个能耗—任务超期成本，不再使用原式(25)的完成时间目标或任务数平均。原式(20)的伪服务器相对改进不在当前训练奖励路径。原式(28)所定义的规范化完工差/能耗相对改善，也没有作为当前 RNN 的显式目标保留。

这会改变任务/VM 的偏好：当前即时延迟项对于所有不超子截止期的任务都是0，原文的相对完成时间改善仍可区分它们。它是目标替换，不能仅记为 alpha 从0.5调到0.75。原文也没有明确要求用式(28)作为 MSE 标签，因此不能以“未做式(28)监督回归”单独判错。

证据：`algorithms/irws_paper/environment.py:109–121`；`algorithms/irws_paper/config.py:4–6`；`environments/irws.py:593–600,744–754`；`algorithms/irws_paper/learner.py:104–106,158–161`。

### A2. 内外奖励融合公式有两处独立改动

原文 p.906 式(30)：

`r = [t(v)/Rank_dn(v)] * r_in + [1-t(v)/Rank_dn(v)] * r_step`。

当前先将权重改成 `lambda = t(v)/(t(v)+Rank_dn(v))`，双零时取0；再改成：

`r_train = r_ext + lambda*r_int`。

即分母变了，外部奖励的系数也从 `1-lambda` 变成恒定1。例如 t=2、Rank_dn=4，原文是 `0.5*r_in+0.5*r_step`，当前是 `r_ext+(1/3)*r_int`。这不是原式的边界补全，而是明确的奖励设计改变；有界的是 lambda，内在奖励 head 的输出本身并未限制在固定区间。

证据：`algorithms/irws_paper/environment.py:34–40,117–119`；`algorithms/irws_paper/learner.py:27–30,130–138`。

### A3. 新增截止期和等待时间观测，扩展任务排序能力

原文 p.904 式(19)为 `Q(e_v^DAG)`，打分只输入任务嵌入。原文 VM 状态列表也没有当前代码新增的三项截止期上下文。

当前任务 Q 输入变为5维嵌入加3维动态特征：任务子截止期剩余、工作流截止期剩余、Ready等待时间。Q实际为 `8 -> 5 -> 1`。VM Actor/Critic也加入这三项，输入维度为 `5+1+3+6N = 9+6N`。

因此，即便两个任务拓扑和资源属性一样，代码也能因为其截止期/等待不同而给予不同选择概率。这是新增可用信息与排序机制，不能仅列作隐藏层参数变化。

证据：`algorithms/irws_paper/environment.py:72–97`；`algorithms/irws_paper/networks.py:62–80`；`algorithms/irws_paper/learner.py:48,81–87`。

### A4. 等待队列系统改为只允许派给空闲 VM

原文 p.901 定义服务器等待队列 Q_l，p.902 式(11)约束 `Q_l <= Q_max`，正文说明目标服务器队列满时分配才无效。p.904 状态包含每台服务器等待任务数量及这些任务的预计执行时间。

当前 `get_vm_obs_and_mask` 和 `paper_step` 只允许 `vm_available_at <= current_time` 的 VM，忙 VM 一律不可选；没有空闲 VM 就推进到下一到达/完成事件。它没有实现原文的可积压服务器等待队列。每 VM 六项实际是：忙闲、距可用时间、所选任务预计执行时长、算力、带宽、需传输数据量。

例如服务器正在执行任务但等待队列未满时，原文可以继续向其排队；当前对应 VM 被直接屏蔽。这改变了动作可行域、状态语义与调度时机。

证据：`algorithms/irws_paper/environment.py:86–112`；`environments/irws.py:790–799`。

### A5. PPO 概率比从服务器动作改为任务与 VM 的联合动作

原文式(19)单独选择任务；p.904 Action明确为所选任务的目的服务器，式(23)使用服务器策略的概率比。

当前 PPO 保存并重算 `task_logp + vm_logp`，形成：

`ratio_joint = P_new(task)/P_old(task) * pi_new(VM|task)/pi_old(VM|task)`。

随后对这个联合比率裁剪。这样任务概率变化会参与 PPO 的裁剪和嵌入元梯度，已经改变优化问题，不是只多保存一个日志字段。

证据：`algorithms/irws_paper/learner.py:139–147`。

### A6. 增加原文公式没有的熵正则

原文式(22)、(32)的目标没有熵项。当前 Actor loss 在 clipped surrogate 之外增加任务熵与 VM 熵的奖励：

`L_actor = L_clipped - 0.01*(H_task + H_VM)`。

它改变探索偏好，也进入虚拟内步及元梯度链。系数0.01另列在参数部分。

证据：`algorithms/irws_paper/learner.py:146–147`；`algorithms/irws_paper/config.py:28`。

### A7. 元梯度是真实可微链路，但采用了不同代理目标

当前并非没有元梯度；`create_graph=True`、虚拟参数及两组外层求导均真实执行。但它不是式(34)–(39)的逐式实现：

1. 虚拟内步为一次 `theta_fast = theta-actor_lr*grad(L_actor)`；真实网络更新使用 Adam。虚拟步没有展开真实 Adam 的动量与二阶矩历史。
2. phi 外层为 `mean(exp(fast_VM_logp-old_VM_logp)*discounted_cost_to_go)`。原式(35)包含 PPO clipping 生效条件和优势因子，当前这个外层没有相同条件或额外优势因子。因此差异超过“把无穷和截短”。
3. eta 外层使用更新后 VM 的 clipped PPO surrogate，再对任务嵌入/打分网络自动微分，不是直接执行式(37)–(39)的显式近似梯度。
4. phi 的 cost-to-go 在每段 rollout 尾部固定以0作未来值，非终止边界也如此；这是有限成本轨迹截断。Actor/Critic 的真实下一决策 bootstrap 是另一条路径，不能把二者混为一谈。

证据：`algorithms/irws_paper/learner.py:149–176,185–201`；四组 Adam 初始化在 `:54–57`。

### A8. Algorithm 1 的采样、更新时机和更新粒度改变

原文 Algorithm 1 第3–11行按 interval 调度；第12–20行从 memory随机抽 minibatch，且按伪代码在 `j=1..Sze` 内依次更新四网络；第21–22行更新行为策略、清内存。

当前是连续事件决策，收集64条连续转移或episode尾段后，直接对整个buffer的均值损失执行一轮四优化器更新，然后清空buffer。没有原文随机抽样这一环。原文没有提供 S 的明确数值，不能声称代码的 S=1 与某个已知原文数值不同；但默认训练循环和采样语义确实不同。

证据：`algorithms/irws_paper/runner.py:62–82`；`algorithms/irws_paper/learner.py:119–121,147–148,172,197–201`。

## 二、公共物理环境适配：应披露，但不能混称为网络算法错误

**还发现聚合实现中的一个确定退化性质。** `networks.py:31` 的 `softmax(Wself*x_v + Wneighbor*states, dim=0)` 沿邻居轴运算时，`Wself*x_v` 对每个邻居相同，会因Softmax平移不变性被抵消。实际注意力等于 `softmax(Wneighbor*states, dim=0)`，self_weight没有有效的self-query作用（self状态仍可通过states集合及GRU路径起作用）。

## 五、核查边界与可采用的表述
