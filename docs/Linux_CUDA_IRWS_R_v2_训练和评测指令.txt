# 二、评测：9条组合命令，每条完成本场景及两个泛化场景

# IRWS-R v2：本场景与两个泛化场景的组合评测命令
# 日期：2026-10-26。在Linux项目根目录运行，先激活已有CUDA版PyTorch环境。
# 共9个独立命令组；每组固定一个已训练的S任务模型，依次评测S、M、L三个任务档。
# 每场景使用测试种子700-729，共30个实例；每组90次，全部9组共810次实例评测。
# 资源S：SS -> MS -> LS；资源M：SM -> MM -> LM；资源L：SL -> ML -> LL。
# 每块整体复制执行即可后台完成三个场景；按需选择命令块，不要直接运行整个清单。
# 同组内部顺序运行；不同组可按服务器资源情况并行，CUDA_VISIBLE_DEVICES=0按实际分配调整。
# 统一加载对应源训练场景的best模型；--train-task始终为S，资源与截止期在组内固定。
# 沿用附件现有模型配置：queue-capacity=10、slot-duration=1，不使用尚未实施的加速方案。
# 沿用已有F22截止期缓存及f19共享归一化文件；不重新训练、校准或生成缓存。
# bash -e保证任一场景失败就停止该组；全部完成后日志打印ALL_DONE。
# 各场景CSV/JSON/逐种子明细仍由原评测入口分别保存；已有结果目录非空会报错停止。
# 组日志和PID使用新的source..._SML名称，便于区分原来的单场景控制台日志。
# 再次运行同一组会覆盖同名组控制台日志与PID；请先确认该组未在运行且没有需要保留的组日志。

# 源训练场景 SS/Tight：SS -> MS -> LS，每场景30个测试实例
mkdir -p outputs/server_console_logs
CUDA_VISIBLE_DEVICES=0 nohup bash -ec '
python -c "import torch; assert torch.cuda.is_available(), \"CUDA unavailable: stopped\"; torch.ones(1, device=\"cuda\"); print(torch.cuda.get_device_name(0))"
for task in S M L; do
  echo "[START] task=${task} resource=S deadline=Tight source=SS/Tight seeds=700-729"
  python -u launch.py algorithms/irws_r_v2/evaluate.py \
    --task "$task" --resource S --deadline Tight \
    --train-task S --train-resource S --train-deadline Tight \
    --seeds 700-729 --model-seed 1 \
    --experiment-protocol configs/f22_split_v1.json --normalization-mode f19_shared_v1 \
    --queue-capacity 10 --slot-duration 1 --device cuda
  echo "[DONE] task=${task} resource=S deadline=Tight"
done
echo "[ALL_DONE] source=SS/Tight targets=S,M,L seeds=700-729"
' > outputs/server_console_logs/eval_irws_r_v2_sourceSS_Tight_SML_model1.log 2>&1 &
echo $! > outputs/server_console_logs/eval_irws_r_v2_sourceSS_Tight_SML_model1.pid
