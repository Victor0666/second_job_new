Linux / Bash 独立 CUDA 训练命令
================================

共81条独立训练命令：正式学习基线27条，主算法及5个消融54条。
每个算法分别训练 SS、SM、SL × Tight、Medium、Loose，共9种情况。
每条命令只启动一个场景，600 episode，模型初始化种子1。
ERTF-H-FIFS是启发式，无需训练；新版IRWS使用irws_paper，未列历史简化irws。

一、启动前（每个终端先执行）
--------------------------------
# 先进入服务器上的项目根目录，再激活该服务器的Python环境。
# 若使用Conda，请用实际的conda activate命令替代下一行。
source .venv/bin/activate
mkdir -p outputs/server_console_logs
nvidia-smi

# 核对九组缓存和九个源训练场景的默认校准配置；检查通过再启动训练。
python launch.py common/f22_cache.py --all
python -c "from common.f18_calibrate_normalization import nine_scenarios; [s.normalization_metadata() for s in nine_scenarios()]; print('All nine normalization scenes OK')"

二、并行执行说明
--------------------------------
1. 以下命令各自独立，可逐条复制到Bash执行。每条末尾的 & 表示后台运行。
2. CUDA_VISIBLE_DEVICES=0表示物理GPU 0。把单条命令中的0改为1、2等，即可分配到其他GPU。
   如果在Slurm等调度系统内运行，应遵守作业分配的GPU设置，不要擅自覆盖调度器设置。
3. 各任务使用独立日志、PID文件和已有的独立模型目录。不要重复启动同一算法、同一场景。
4. 每条命令启动时都会检查CUDA；不可用会退出，不会静默使用CPU。
   PD3QN、MARL、MAHDRL及消融自动选择CUDA；新版IRWS显式使用--device cuda。
5. 请按GPU显存、CPU核心和内存选择并发数，不要一次粘贴执行全部81条。
   同一GPU可运行多个任务，但显存不足会失败；环境仿真仍使用CPU。
6. nohup允许退出终端后继续运行。PID文件记录进程号，不代表训练成功；请检查日志。
7. 当前命令使用已安装的默认校准配置和F22协议，不重新校准，不改动已有缓存。
8. 如使用不同--model-seed重复训练，需同步修改日志和PID文件名。已有训练目录会受到覆盖保护。
