Linux / Bash：全部算法27场景、30种子顺序泛化评测指令
==============================================================

共10个算法/变体：9个学习算法及消融，外加ERTF-H-FIFS启发式；不使用旧简化IRWS入口。
每个算法：9个独立命令组 × 每组3场景 × 每场景30种子 = 810次实例评测。全部合计8100次。
九个命令组对应：源训练SS/SM/SL × Tight/Medium/Loose。命令只评测，不训练。
资源S：SS -> MS -> LS；资源M：SM -> MM -> LM；资源L：SL -> ML -> LL。
同组始终使用同一资源、同一截止期、S任务训练得到的best模型，模型种子1。
每场景种子为700–729；先完成S场景的30个种子，再M，最后L。

一、准备（在项目根目录执行）
--------------------------------------------------------------
# 确保服务器已更新至包含逐种子保存修复的代码；Python使用3.12，PyTorch需支持服务器GPU。
# 激活服务器上的实际Conda环境，例如：conda activate second_job_new
python --version
git log -1 --oneline
mkdir -p outputs/server_eval_logs
python launch.py common/f22_cache.py --all
python -m unittest common.test_incremental_evaluation -q

二、执行与保存规则
--------------------------------------------------------------
1. 每个命令块单独启动一个后台任务，内部三个场景依次运行；不同命令块可以按资源情况并行。
2. 每个命令块已包含mkdir，避免日志目录缺失。不要一次启动全部90个任务。
3. GPU默认0，修改CUDA_VISIBLE_DEVICES=0即可选其他GPU；使用作业调度器时遵守其设备分配。
4. 学习算法先检查CUDA是否可用，否则停止；MARL和新版IRWS显式传--device cuda。启发式没有网络推理，不要求CUDA。
5. 所有场景固定F22、模型种子1、测试种子700–729、F19编码。默认读取已冻结的校准配置。
6. 源训练模型必须已存在；缺失或某场景出错，该命令组停止，不会悄悄改用其他模型。
7. 每完成一个种子，立即刷新主结果CSV和该种子明细文件，不等待30个种子全部完成。
   新版IRWS的summary.json仍在30个种子完成后生成；中断前已保存的CSV/明细保留。
8. 场景之间使用独立结果路径，不会将SS/MS/LS写进同一张场景CSV。控制台日志按源训练组保存。
9. 不要重复启动同一算法/资源/截止期组。旧式主CSV重跑会追加重复seed，IRWS主CSV则重新开始。
   重跑前备份对应场景输出；本文不承诺自动断点续评。
10. 不修改训练脚本，不新增checkpoint，不重生成缓存与校准；评测的是best模型。

所有算法新增统一明细：
  episodes/seed700.json 等：逐种子指标与决策计时；
  workflows/seed700.csv 等：该种子的逐工作流明细；
  decisions/seed700.json 等：该种子的逐分配计时。
除新版IRWS外，统一明细位于：
outputs/run/review_metrics_v1/<algorithm>/<output_version>/<场景_截止期_model1>/
新版IRWS位于其outputs/run/irws_cloud_energy_tardiness_v2/.../<场景_截止期>/measurements/。
主CSV保留各算法原有目录；控制台会显示保存路径。

本文件提供命令，不会自动执行正式评测。
