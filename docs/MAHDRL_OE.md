# MAHDRL-OE：观测增强与分配能耗归因

算法 ID 为 `mahdrl_oe`，是从当前 MAHDRL 建立的独立变式，仅实施讨论中的第 1、2、3、5 项。原 `algorithms/mahdrl` 与 `environments/mahdrl_fcfs.py` 的行为不变，新变式的代码、模型、日志和评测结果分别隔离。

## 修改内容

1. **HA/VA 截止期观测**：追加有正负号的任务子截止期剩余时间，保留工作流截止期和原观测；VA 追加各候选 VM 的预计超期量。
2. **VA 主机信息**：追加所选主机 one-hot、空闲功率、当前功率，以及各候选 VM 的即时功率变化。即时功率变化是输入特征，不是完整任务能耗估计。
3. **HA 候选主机摘要**：对每台主机的原合法空闲 VM，提供最快执行时间及其对应能耗、最小预计超期量、最低增量能耗及其对应执行时间。最快与最低能耗可能属于不同 VM，因此保留配对关系。没有合法空闲 VM 时填零并沿用原动作掩码。
5. **HA/VA 能耗奖励**：追加任务前后，使用相同公共功耗模型计算已知排程的能耗差分；包含负载重叠、主机任务窗口扩展和内部空闲。常规分配即时返回该差分，phase 不重复发放；原异常强制分配产生的尚未发放增量在 phase 补发。

没有实施第 4 项：不新增截止期动作筛选、不强制选择最快或最低能耗 VM。TA 观测、243 个动作、排序、决策频率和 phase 奖励不变。原超参数、隐藏层、延迟奖励与权重、公共物理执行规则保持一致；新增观测相应改变网络输入层尺寸。

## 输入布局与尺度

新增字段追加到原观测之后，原字段次序不变。设主机数为 `H`、每台主机最大 VM 槽位数为 `M`：

| 智能体 | 新增布局 | 新增维度 |
|---|---|---:|
| HA | 任务子截止期剩余时间；每台主机 `[最快时间, 其能耗, 最小超期量, 最低能耗, 其时间]` | `1 + 5H` |
| VA | 任务子截止期剩余时间；主机 one-hot；`[空闲功率, 当前功率]`；每个 VM `[预计超期量, 即时功率增量]` | `1 + H + 2 + 2M` |

时间除以源训练场景的 `T_ref`，功率除以固定 `100 W`，能耗除以 `100 × T_ref J`。不使用验证或测试结果拟合尺度；评测沿用源训练场景。带符号的截止期剩余量不截为零。

## 奖励与物理指标

对一次任务分配，`ΔE = E(追加后的已知排程) - E(追加前的已知排程)`。`E` 仍按每台主机自身的首个至最后一个任务窗口积分，不引入休眠或开关机规则，不预测尚未决定的后续分配。单次任务只改变所选主机的记录，因此全局与所选主机的本次排程增量相同。

HA/VA 保留原能耗缩放和延迟权重。最终总能耗继续来自原物理统计，TA 继续依据原物理区间能耗计算 phase 奖励。对完整正常结束的回合，分配能耗增量之和应等于最终物理能耗。截断回合的增量覆盖已安排任务的完整执行区间，可能与截断时刻前的物理能耗不同。

能耗反馈提前会改变 `gamma < 1` 时的折扣回报时序，即使未折扣能耗总和守恒，学习目标也不完全等同于原版。

## 运行

从项目根目录运行，新算法沿用原场景参数和公共实例缓存：

```powershell
python -m algorithms.mahdrl_oe.train --dry-run
python -m algorithms.mahdrl_oe.evaluate --dry-run
python -m algorithms.mahdrl_oe.train
python -m algorithms.mahdrl_oe.evaluate
python -m unittest common.test_mahdrl_oe
```

新算法模型路径使用 `mahdrl_oe` 名称，并携带变式元数据。原 MAHDRL 权重不适用于新增输入与奖励协议，必须独立训练。

## 验证边界

验证覆盖新增观测、原动作掩码、候选查询无物理副作用、重叠与内部空闲的能耗增量、原/新固定动作轨迹一致、TA 奖励一致、增量守恒与 phase 防重复，以及临时目录内的小网络训练/保存/加载/评测。

本次新增的 7 项测试已通过；场景注册的 4 项原回归测试也已通过。微型训练使用 2 个工作流、`(16, 8)` 隐藏层、1 个训练回合，三层均发生实际梯度更新，模型保存/加载和评测均在临时目录完成。

最终完整回归通过：`python -X utf8 -B -m unittest discover -s common -p "test_*.py" -q`，共 199 项（93.413 秒）。Windows 下直接使用系统默认 GBK 会使两项既有测量测试读取 UTF-8 文件失败；项目 `run.cmd` 已启用 `-X utf8`，本次未改写这些原测试。独立只读核对的 1200 次随机区间追加也验证了候选预览、提交与公共完整积分差分一致。

小网络验证只说明入口和数据链路能够运行，不说明正式策略性能。是否降低能耗且不降低成功率，仍需在相同配对实例、训练预算和评价口径下正式训练比较；本次不据此声称性能改善。
