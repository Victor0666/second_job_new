# MAHDRL 节能改进：先保护成功率，再改善能耗决策

调研日期：2026-10-21。范围：当前工作区的 TA/HA/VA 三层 D3QN，以及 Zotero 本机文献库和论文原始来源。本文是实施建议，没有修改算法、训练模型或宣称取得节能结果。

## 摘要

针对“保持工作流成功率、降低能耗、尽量少改 MAHDRL”的目标，本次先检查实现，再从节能调度、强化学习方法、近期研究与反证三个视角检索。Zotero 中筛出 113 条相关题录，按 DOI 或标题去重得到 49 篇候选；重点阅读库内 CEAS、DQN-Edge、QPHH、ULS 四篇全文，并交叉核验相关基础文献。证据支持优先保留三层 D3QN，修正能耗优先的选模规则，再向 HA/VA 提供与本项目记账一致的候选边际能耗。带截止期检查的少量动作重排可作独立试验，PER 和奖励塑形放在后续。现有论文不能直接证明这些改动在本项目中保证成功率不降，必须用固定协议下的配对实验验收。

## 1. 要回答的问题与证据边界

RQ1：当前实现中，哪些机制可能导致能耗目标与用户目标不一致？

RQ2：哪些文献措施能在保留三层结构、固定 VM 和当前物理模型的条件下迁移？

RQ3：如何判断节能没有以成功率下降为代价？

这里的主要成功率是工作流按自身绝对截止期完成的比例。任务子截止期成功率、超期总量和最终完成率另行报告，不能互相替代。可靠性文献中的硬件无故障概率也不能直接当作本项目按时完成率。

本机 `outputs/ckpts` 和 `outputs/logs` 当前没有模型文件或训练日志；`outputs/run` 主要是其他算法的轻量记录。因此，本文能确认实现和可行改法，不能量化用户所说的性能欠佳，也不能给出可信的预期降耗百分比。README 部分前置条件说明已过时，应结合 `docs/R17_ready.md`：新版缓存和校准材料已经准备，但这不代表正式模型训练、测试已完成。

## 3. 项目中已经存在的机制与真正缺口

| 检查项 | 当前实现事实 | 对改进方向的影响 |
|---|---|---|
| 正式环境 | `algorithms/mahdrl/train.py` 导入 `environments/mahdrl_fcfs.py`，后者继承 HEFT 基类实现 | 应以 FCFS 子类的最终奖励为准，不能只看基类的 Manager 注释 |
| 结构和动作 | TA 调整五项任务排序权重，HA 选主机，VA 选所选主机内的 VM | 保留三层及现有离散动作，无需引入 PPO、GNN 或每 VM 一个新智能体 |
| 任务排序 | F15 已包含随当前时间变化的 slack、EDF、HUR 等属性 | “增加 EDF/动态 slack”不是新措施；只有候选 VM 特定的剩余余量才是额外信息 |
| 完成时间 | `_task_duration` 和 VM 的 `pred_finish` 已按父任务实际放置计通信 | 不必重复建立通信预测；应复用当前函数 |
| 通信 | 仅同 VM 免父子传输，同主机不同 VM 仍计传输 | 不可直接照搬“同 host 免费通信”或网络拓扑节能模型 |
| 资源限制 | 仅空闲 VM 可立即分配；没有排队、迁移、DVFS、睡眠动作 | 不能将降频、等待忙碌父 VM、任务运行中迁移称为小改动 |
| 物理能耗 | 各 host 首任务开始至末任务结束的窗口积分，内部 idle 计入；从未使用的 host 不计 | 少开主机、尽快完成和复用旧主机都只能是候选，必须比较完整窗口增量 |
| 资源观测 | HA 的每 host 五维以容量和运行状态为主；VA 每 VM 五维含 PC、BW、空闲和完成时间，无显式候选边际能耗 | 让策略看到当前动作的物理能耗差，比继续加深网络更值得先试 |
| 奖励 | 训练中三层的延迟权重均设为 0.75；HA 用全局区间能耗，VA 用所选 host 区间能耗；下层 tardiness/300 裁剪到 1 | 权重 0.75 不是“成功率优先”的约束，降低平均 tardiness 也不等于减少失败工作流 |
| 选模 | `train.py:463` 只比较 `eval_energy < best_eval_energy`；协议的 selection 同样写 minimum validation total energy | 当前 best 允许用较差成功率换较低能耗，应首先补验收门槛 |
| 数据划分 | F22：训练 0–599，验证仅 600，测试 700–729；训练随机种子与实例种子分开 | 单验证实例容易选中偶然有利模型；扩充验证应另建统一协议版本 |
| Replay | 正式导入 `d3qn_agent_EXDehid.py`，采用均匀 replay；另有 PER 文件 | PER 尚未启用，但不是一行导入即可公平替换 |

现有边际能耗代理 `_estimate_marginal_energy_proxy` 只计算 `(P_after-P_before)×duration`。全项目搜索表明，这个方法当前没有被正式 MAHDRL 路径调用。因此，它的不足是“新策略复用时需要先修正的问题”，不能说它已经导致现有 MAHDRL 的能耗偏高。F11 的真实下一决策 bootstrap、pending reward 结算和能耗审计也已经存在，未发现依据可把它们重新列为已确认缺陷。

### 3.1 用项目功耗函数复核一个容易误判的例子

使用实际 S 资源配置 `(9,8,8)`，host 0 的总 PC=34，空闲功率=15.9 W。假设分配 PC=1、持续 10 秒的任务：

| 情形 | 增量能耗 |
|---|---:|
| 旧代理只算功率差乘时长 | 12.9412 J |
| 从未使用的 host 上执行该任务，按公共函数积分 | 171.9412 J |
| host 曾在 `[0,1]` 执行任务，再在 `[101,111]` 执行该任务 | 1761.9412 J |

第一种估计漏掉新窗口内的基础功耗 159 J；第三种还追溯纳入 `[1,101]` 的 100 秒内部空闲，即 1590 J。数值由 `common.workflow_opt.energy_from_records` 计算，并用断言验证两个差值；记录见相邻的 `MAHDRL_energy_literature_diagnostics_2026-10-21.json`。这是功耗诊断例，不是算法对比实验。

## 4. 文献如何支持和限制小改动

### 4.1 时间约束下比较放置能耗，有依据；固定优先某类资源，没有普适依据

CEAS [1] 和 MOHEFT [2] 都将执行时间与能耗结合，但 CEAS 包含 VM 重用、合并和 DVFS，MOHEFT 保留时间—能耗 Pareto 候选；两者都不支持用“低 PC”直接替代能耗计算。QPHH [3] 的主机负载与非线性功耗积分更接近本项目物理成本的形式，但使用全局执行窗口，其整套离线种群搜索并不适合直接替换在线三层决策。可提取的是候选放置的物理成本计算，而非照抄算法或收益。

CEAS [1] 提供同 VM 消除父子传输和条件化重用的正面依据，而 EESF [4] 的出版社摘要明确指出依赖任务同 VM 并不总是节能。两者的张力提示：locality 应影响带通信的完成时间和能耗比较，不能升级为硬亲和规则。当前已有 `_task_duration`，先用它算实际差异即可。

| 文献 | 可迁移内容 | 关键限制 | 本次阅读范围 |
|---|---|---|---|
| CEAS [1]，TSC 2018 | 在时限条件下选择/重用资源，同 VM 降低父子传输 | slack reclamation 依赖电压/频率调整；合并会改变 DAG | Zotero 全文 |
| MOHEFT [2]，FGCS 2014 | 时间和能耗联合比较，保留非支配候选 | 其计能方式不等于本项目 host 首末窗口；Pareto 权衡不保证成功率 | 公开作者稿全文 |
| QPHH [3]，TSC 2025 | 利用 host 负载和非线性功耗计算候选成本 | 静态全局搜索；全系统窗口与本项目不同 | Zotero 全文 |
| EESF [4]，Parallel Computing 2025 | 资源速度需与任务需求匹配，同 VM 放置可能存在反例 | 含动态资源配置，不能搬入固定 VM 池 | 出版社摘要及书目核验 |

### 4.2 deadline 的保护需要独立指标，奖励加权和局部过滤不能代替它

DQN-Edge [5] 用时间/能耗两个价值网络及上下文注意力平衡目标，ULS [6] 则显式研究多工作流竞争下的实时紧迫度。前者提示动态权衡有研究依据，后者提示资源竞争不能被单任务 EFT 代替；两者都不能证明给当前 MAHDRL 加一个能耗权重就保住成功率。项目已有五项任务排序和动态 slack，不值得先搬入注意力双网络或完整 ULS。

CPO [7] 将约束与优化目标分开，而正式 shielding [8] 依赖正确环境抽象、安全规范及可维持安全的动作集合。对本项目可借鉴前者的约束表达和后者的保护思路，但普通 D3QN 的成功率门槛筛选不是 CPO，基于估算 EFT 的 mask 也不是继承形式保证的 shield。

一个自造反例说明局部检查的边界：A、B 同时 ready，F、S 两个 VM 空闲，工作流 deadline=2.5；A 在 F/S 上耗时 1/2，B 在 F/S 上耗时 2/4。先令 A→F，A 的 EFT=1 合法，但 B 最早等 F 到时刻 1 再运行，完工 3；若 A→S、B→F，则都在时刻 2 完成。故当前任务按时不等于整个工作流可续排。该例用于说明有限资源竞争，不是论文实验结果。

### 4.3 改善学习效率有依据，但不会自动带来节能或成功率保证

PER [9] 用 TD error 优先复用经验，Foerster 等 [10] 则指出其他智能体变化会让历史 replay 陈旧。合起来看，三层同时学习时应同时考察采样效率和非平稳性，不能把高 TD error 全部当作有价值的节能经验。PBRS 的单智能体理论 [11] 与多智能体分析 [12] 支持规范的势差塑形，但后者也说明保持均衡集合不等于保持某次训练最终收敛到的联合策略。因此，两类方法适合后续单因素实验，不适合作为本次成功率保护的依据。

## 5. 推荐措施及最小落地方式

以下是结合文献和项目模型提出的适配方案，均需实验验证，不是对原论文的逐步复现。

### 5.1 P0：把成功率门槛加入模型选择

这是最先要做的验收修正，不是独立的节能算法。以固定 baseline 在同一验证集上的工作流成功率为门槛，在合格 checkpoint 中选最低能耗：

`eligible = SR_val(candidate) >= SR_val(baseline)`

`best = argmin Energy_val(candidate), among eligible checkpoints`

baseline 必须也在候选集合中；没有合格且更省能的模型就保留 baseline。若允许非零容忍差，必须在看测试结果之前由研究目标明确，不能事后放宽。最好同时限制各验证实例不发生 baseline 按时而 candidate 超时的回退，而非只看合并平均数；这是更严格的有限验证集规则，也不能外推为总体保证。

改动集中在 `algorithms/mahdrl/train.py` 的验证返回值和保存条件。`collect_validation` 已记录成功率，直接让验证函数显式返回/汇总公共 `episode_metrics` 即可，不应让正确选模依赖可关闭的日志开关。保持原三网络和动作空间。若已有一组可用 checkpoint，只需重评估；当前本机没有这些文件，后续训练应保存能耗—成功率非支配候选或同时保留两个 best，避免所需模型早被覆盖。

单个验证 seed 600 可以先实现门槛，但不足以选稳定策略。建议另建统一协议，例如验证 600–609，训练和测试保持原名单；所有对比方法共享相同新协议和预算，不能在 F22 名义下只给 MAHDRL 增加验证题目。缓存与校准元数据的协议绑定也需按项目规则检查，不能只修改标签。

### 5.2 P1：向 HA/VA 提供与计能窗口一致的候选边际能耗

这是最值得优先尝试的实际节能改动。保留网络类型、层数、输出动作、排序、奖励和事件推进，只增加很少的物理成本输入。

对于当前任务 i 和合法空闲 VM v，在临时记录上构造：

`finish_v = now + _task_duration(i, v)`

`deltaE_v = energy_from_records(records + candidate_record_v, hosts) - energy_from_records(records, hosts)`

两次积分都用同一份“已知、已排定任务的完整轨迹”，不传入只截到 now 的端点，不改真实环境，也不预先执行任务。这个差值精确对应当前已知预约记录下的增量，包含新主机基础功耗、已有任务结束事件和内部空闲窗口扩展；它仍不包含未来未知工作流和后续决策的影响，不是最终 episode 成本的完美预测。

VA 每个候选 VM 增加一个归一化 `deltaE_v` 即可；现有 `pred_finish` 已提供时间信息，不重复增加。HA 每个 host 增加一个该 host 空闲候选中最低的 `deltaE_v`，可再增加该低能耗候选对应的相对完成时间，避免 HA 只见能耗不知道速度。若先用子截止期筛选后取最小值，须同时给出“存在可行候选”的标志；无可行候选时不能用 0 冒充低能耗。

实现入口是 `environments/mahdrl_heft.py` 的两个观测构造函数，以及 `host_feat_dim/vm_feat_dim`。候选仅影响所选 host，可把公共积分限制到该 host、一次决策缓存已有能耗，先验证与公共函数一致再优化；不能在所有记录上反复全量积分后忽略决策延迟。归一化尺度只从训练/校准数据得到，更新观测版本、归一化映射和 checkpoint 标记。输入维度改变需要重新训练，不能强行加载旧第一层权重。

新增特征应保留真实能耗奖励。不要把预测 `deltaE` 再重复加到同一物理奖励中，也不要用当前未调用的 `ΔP×duration` 代理直接替换它。

### 5.3 P2：仅在有余量时，对少量候选进行节能重排

若希望先不改变输入维度，可把此项作为 P1 的替代试验，而不是一开始两项叠加。保留原始 HA/VA 给出的动作，另外保留少量 Q 值接近的合法候选；只对有充足子截止期余量的任务比较上述 `deltaE`。低 slack、关键路径风险高或无合适候选时回退原始策略。

筛选条件至少包含当前真实通信后的 `finish_v <= task_subdeadline - margin`，并检查剩余路径的乐观完工界；这些检查只能排除明显不利选择，不能证明全局可行。HA 先检查该 host 是否存在候选，VA 再选同一候选集合内的 VM，不能 HA 挑到一个只在其他 host 才有可行 VM 的分支。保留 baseline 动作和空集回退，禁止把回退解释为“已保证 deadline”。

parent VM 若当前空闲，其通信优势已经体现在 `_task_duration` 中，可自然进入候选；不为 locality 等待忙 VM，也不额外给予无条件亲和 bonus。Q 接近阈值、margin 和候选数只能用验证集确定。先对旧模型离线重评估可不重训；若长期采用该动作规则，应记录真正执行动作，并一致更新行为、探索和 Double DQN 下一状态选择规则后重训。

这比 P1 更直接干预 learned policy，也可能破坏跨任务资源分配，优先级更低。若用户要求的是所有未来负载下的严格零回退，则需要可行续排证书或资源预留，这已经超过本次低改动范围。

### 5.4 P3：学习效率候选，每次只开一个

**PER：** 可以先仅对 HA 或 VA 实验，TA 保持均匀 replay。但不能直接把当前 import 改到 `d3qn_agent_PER.py`：现文件的 Dueling head 每支只有一个隐藏层，正式 EXDehid 每支两个；PER buffer 是 list，而训练的 `_warmup_ready` 读取 `buffer.maxlen`，TA 走到此处会不兼容。公平方案是在保持当前 Q 网络不变的前提下迁移采样、逐样本 IS 权重和 priority 更新，再适配 warmup。多智能体旧数据风险需结合 transition 年龄与学习曲线诊断。它提高采样效率的可能性不等于节能保证。

**PBRS：** 保留原奖励，可试 `r' = r + kappa*(gamma*Phi(s_next)-Phi(s))`，使用该层真实 replay 转移、gamma=0.95、固定有界势函数以及终止势 0。不要把“预测省多少电就加多少 bonus”称为 PBRS；不要直接用“本次增量能耗”的动作函数冒充状态势。单层先试，检查边界和结算，需重训。其保持的是相应理论条件下原目标的最优解/均衡集合，原加权目标仍可能牺牲成功率 [11,12]。

**VA 局部能耗改为全局能耗：** 项目已有 TL/TL_2 接线，可低成本参考，但不是本次首选。TL_2 移除了 HA，不能用它的结果证明三层 MAHDRL 改全局 VA 奖励有效。全局项有机会对齐系统目标，也可能增加 VA 的无关噪声；应作为独立消融，同步修改直接和延迟奖励、审计及版本隔离，不能只改一处公式。

## 6. 最小实验顺序和验收标准

| 阶段 | 唯一主要变化 | 要回答的问题 |
|---|---|---|
| A | 同一 MAHDRL 的 checkpoint 成功率门槛 | 目前是否只是挑错了模型？ |
| B | A + 候选真实边际能耗输入 | 显式物理成本是否能改善节能决策？ |
| C | A + 小范围候选重排，先不叠加 B | 无需改网络是否已有可用收益？ |
| D | 在较好方案上单独加 PER 或 PBRS | 学习效率措施是否提供额外收益？ |

先固定 SS/Tight，再验证同资源下任务规模泛化；进入完整结果前覆盖项目原有资源和截止期条件。宽 DAG、链式 DAG、到达密集条件应单列观察，因为平均成功率可能掩盖关键场景回退。若增加到达率压力测试，另建独立版本并给所有算法相同实例，不能混入原协议结果。

每个方案采用相同训练预算、校准尺度、DAG、到达、payload、alpha、VM 与实例随机数；先用 3–5 个模型随机种子筛查，最终预算允许时扩到更多独立训练。这个数量是预算建议，不是统计保证。验证集只用于选择，测试 700–729 在规则冻结后使用，不对它逐次调阈值。可先调试小范围，正式比较仍用同一完整测试名单。

至少报告：全部尝试的总能耗、工作流按时成功率、完成工作流数、超期总量、makespan、任务子截止期成功率，以及新增候选计算的决策延迟。另报 baseline 成功而改进方案失败的逐工作流数，避免只看平均数；双方都成功实例上的能耗可作辅助指标，不能代替全体能耗。

以同一模型种子和实例做配对，报告 `DeltaSR` 与能耗差的区间；bootstrap 要尊重模型种子和 episode 的聚类结构，不能把同一 episode 的 50 个竞争工作流都当成独立训练。RL 评估文献 [13] 支持报告运行分布和统计不确定性，而非只取最好 seed。成功率“差异不显著”不能推出“不下降”：若预设允许下降 delta，应要求 `DeltaSR` 单侧置信下界高于 `-delta`。本需求默认 delta=0；有限样本即使点估计相同，也通常不足以证明所有负载上的严格零下降。

实际接受规则是：预先固定的验证与测试对比中，成功率满足既定门槛，未出现不可接受的逐实例回退，总能耗下降且区间支持该结论；否则保留 baseline。若成功率证据不足，应写“观察到成功率持平，尚不能确证总体非劣”，不能写成已有保证。

## 7. 暂不采用的措施与未决问题

不优先采用 DVFS、睡眠/唤醒、动态新增 VM、迁移、DAG 合并、PPO/GNN/Transformer、完整 CPO 或每 VM 一个 agent：它们需要改变本项目物理模型或主要训练结构。CEAS [1] 的降频和 DQN-Edge [5] 的双网络注意力虽有原研究支持，迁移成本不符合本次约束。

不采用“总优先已用 host”“总选最低 PC”“总跟随 parent VM”或直接提高能耗权重。前面已经给出空闲窗口的本地反例，EESF [4] 也限定了同 VM 的收益，成功率约束又不能被有限奖励权重替代 [7,8]。

尚需用正式模型回答：高能耗究竟来自 host 窗口长、跨 VM 通信、关键任务放错资源、选模偏差，还是训练未收敛；当前无训练轨迹不足以排序其实际贡献。P1 的预约增量能否预测未来总能耗、候选计算的时延是否可接受，也都要靠正式运行验证。无需为了这些未决问题先改算法骨架。

## 8. 对研究问题的回答与实施优先级

RQ1：可以确认当前模型选择只优化验证能耗，未落实用户的成功率条件；HA/VA 缺少显式动作能耗差。能耗代理未被 MAHDRL 调用，不能把它误诊为现有运行路径的原因。

RQ2：最契合项目的是“与真实 host 窗口一致的边际能耗 + 现有完成时间/slack 信息”。优先新增少量 HA/VA 物理特征；若先不重训，可独立评估有回退的小候选重排。PER、PBRS、全局 VA 能耗只作为后续单因素候选。

RQ3：成功率应作为独立的模型筛选与实验验收条件。普通 deadline mask、低功率、PBRS 最优策略不变理论或其他论文的高成功率，都不能替本项目证明不下降。

建议执行顺序为 **成功率门槛选模 → 真实边际能耗输入 → 独立评估小候选重排 → 有依据后再试 PER/PBRS**。任何阶段不满足成功率验收，都不采用其节能结果。本文没有运行正式重训和配对测试。
