## 1. 明确改写了原文的训练步骤

### 1.1 Huber 损失替代均方误差

原文 p.14583 式(30)采用平方误差均值，没有重要性采样权重。当前 `common/d3qn_agent_PER.py:269–270` 使用逐样本 `smooth_l1_loss`，再乘 IS 权重求均值。

这是实际损失函数变更。对大 TD error，Huber 的惩罚由平方增长变成线性增长，能减少离群误差对梯度的支配，属于有潜在稳定收益的设计。不能以“都在最小化 TD error”认定与原文相同，也不能由此保证更好的最终能耗。

### 1.2 Polyak 软更新替代周期硬复制

原文 p.14583、p.14585 正文及 p.14584 Algorithm 1 第 23–24 行，明确每隔 `CopyStepLength` 完整复制 E-NET 参数至 T-NET；p.14587 正文选用 60。

当前 `algorithms/pd3qn/train.py:110` 设置 `target_update_tau=0.005`，`common/d3qn_agent_PER.py:295–296` 在每次成功更新后执行：

```text
target = 0.995 * target + 0.005 * online
```

软更新改变目标网络的平滑方式及滞后尺度，有潜在稳定收益。文件中 `target_update_freq=2000` 是 `tau<=0` 时的备用硬同步分支，当前正式配置不执行，不能拿它当当前同步周期。

### 1.3 新样本采用最大优先级，而非入池前计算自身 TD 优先级

原文 Algorithm 1 第 8–12 行及 p.14585 第一段，先计算新 transition 的 Q、目标、TD error 和采样优先级，再放入回放池。

当前 `common/d3qn_agent_PER.py:195–206` 给新样本赋池内最大优先级；不在插入时计算其 TD error。样本被抽中更新后，才在 `:288–292` 根据 TD error 刷新优先级。

这样可让新经验即使当前误差很小，也先获得较高抽样机会。它是常见 PER 实现选择，但确实不同于这篇论文明确给出的插入流程。

## 3. 奖励和问题定义也已实质改写

### 3.1 奖励不再优化原文的总处理时间与设备能耗成本

原文 p.14580 式(17)–(22)对总处理时间与设备能耗做归一化加权，p.14581 式(25)使用 `r=C-cost`。其中远端计算阶段的设备能耗，是 ED 等待结果期间的 idle energy，并不是云主机负载功耗。

当前 `environments/pd3qn.py:777–788` 与 `train.py:70–72` 的默认奖励是：

```text
r = -0.75 * clip(max(0, task_finish-task_subdeadline)/300, 0, 1)
    -0.25 * 0.001 * delta_host_window_energy
```

代码 `pd3qn.py:780` 明确注释“对齐 HRL 下层 delay reward”。这是目标替换，不能解释成仅调整 alpha 或统一单位。

具体差别：两个动作都按时完成时，当前延迟惩罚都是 0，不会因为其中一个更早完成而直接奖励它；超期达到 300 秒后，当前延迟惩罚又会饱和。原文使用归一化处理时间—设备能耗成本，而非仅惩罚超期部分；不过按式(17)–(22)的归一方式，时间和能耗同比缩放时成本也可能不变，因此不能断言原文一定更偏好较早完成的动作。新奖励更直接针对本项目的超期与主机能耗评价，但是否因此改善指标，需要控制实验。

### 3.2 观测与资源动作被改成工作流问题的上下文

原文 p.14581 的状态包括任务数据量、CPU cycles、最大容忍延迟 tau，ED 位置/算力/剩余电量，MS 位置/剩余算力和链路速率；动作是本地执行或卸载至某 MS。

当前 `pd3qn.py:620–640` 的状态为：仿真时间、Ready 数、当前任务 MI/输入量/输出量/子截止期剩余时间，以及每个 VM 的剩余占用时间/PC/带宽。当前动作是全局 VM 索引。

因此，Ready 数、仿真时间、独立输出量和 DAG LF 派生的动态 Slack，都是当前适配版的信息设计；位置、设备电量、本地执行选项则被删除。**原文已有 tau，不能说它原来完全没有截止期信息。** 这些变化有助于处理新问题，但不是原始 MDP 的逐项复现。

当前选模不把超期或成功率作为门槛；因此它是明确面向能耗的模型选择。它与训练奖励的能耗—超期混合目标也并不相同。验证 seed 与测试 seed 分离，没有发现评测期间继续学习或用测试结果更新模型。显式选择 `paired_cloud_protocol_v1.json` 会使用另一套种子，不能与当前默认 F22 混为一谈。

以上参数改变并不意味着全部更优：更大回放池可能保留更多旧经验，更深网络可能更难优化，gamma 更大也可能放大价值误差。没有消融就不能把它们列为已经验证的性能提升。

## 5. 不应误报为额外增强的内容

1. **PER、Dueling、epsilon-greedy 和线性 epsilon 递减原文本来就有。** 项目注释“新增 PER”描述的是项目文件变更，不能用于证明算法比原文多了 PER。
2. **真实后继 Bootstrap 和正确 DAG 完成事件属于修复。** `common/f11.py:184–190`、`pd3qn.py:514–523,718–720` 恢复非终止后继和前驱完成后释放后继。过去全部 done=1 或分配后立即 Finished 是错误，不是原论文限制。
3. **Double DQN 存在原文内部歧义。** p.14582 正文声称解耦动作选择和估值，但 p.14583 式(29)印为 `r+gamma*max_a Q_target(s',a)`。当前 agent `:250–261` 实现标准 online argmax、target evaluate。应披露它与式(29)字面不同，但不能直接判为擅自增强，因为它符合论文名称及正文意图。式(30)的网络下标也有类似表述问题，不影响其明确采用平方损失这一事实。
4. **诊断和记录器不是学习模块。** F11/F19 数值诊断、运行元信息、计时和测量没有添加优化器更新、修改梯度或提供额外调度信息。
5. 真实 PD3QN 调用链没有引入 GNN、Attention、RNN、n-step return、NoisyNet、分布式 Q、辅助损失、学习率 scheduler，以及 MAHDRL 的 OE/GE/PF 等组件。

建议保留必要 DAG/终止语义修复与各算法共享的物理环境，先在论文中明确披露“适配版”。若要判断当前 PD3QN 是否因额外增强而获益，应固定公共环境、模型种子、训练预算和选模协议，分别消融 Huber/IS 权重、目标网络软更新、最大新样本优先级、梯度裁剪及输入预处理；网络和训练参数差异也需单独报告。单独切到 `legacy` 只改变观测处理，不能恢复原论文。

最终判断：**“存在原文外设计”可以确认；“这些设计必然增强性能、造成当前算法比较结果”尚不能确认。** 如果对外声称严格复现，以上明确改写需要恢复或披露；如果研究的是统一云工作流场景下的算法比较，应完整列出这些适配和附加训练设计。
