# 场景入口合并与配置修正

## 合并方式

- 八种学习算法各使用一个 `train.py` 和一个 `evaluate.py`；启发式使用一个 `evaluate.py`。
- 九个截止期预计算脚本合并为 `common/precompute_deadlines.py`。
- 任务分布、资源规模、截止期概率、缓存和模型目录由 `common/scenarios.py` 统一配置。
- 对合并前的 314 个入口逐一做语法树对比。在提取场景参数、统一结果命名、应用以下修正后，共用实现的训练/评测流程一致。

## 已修正的问题

1. **缓存与任务规模不一致。** 某些旧 M/L 场景仍引用 S 场景缓存，包括部分 HOSTRAND 场景。现在所有算法都按实际 `--task`、`--resource` 选择缓存；不再依赖宽泛的文件搜索替换缓存。
2. **MARL L/Medium 主机数量不匹配。** 旧训练入口声明 9 个主机，却只提供 8 组 VM。现统一为 9 个主机，VM 分配为 `(9,9,9,8,8,8,8,8,8)`，共 75 个。
3. **IRWS 保存和加载目录不一致。** 旧训练使用 `ckpts_irws_ppo_*`，评测使用 `irws_task*_res*_mix_*`。现在训练与评测统一采用后者；已有其他目录可通过 `--checkpoint-dir` 显式选择，不自动搬迁或覆盖历史权重。
4. **启发式正式入口路径错误。** 原 main 中缓存路径含 `../outputs/deadlines`，现直接使用项目内 `data/deadlines`。
5. **缺失场景入口。** 原 MARL 缺少 taskL/resM/Medium 文件；统一入口现在支持完整 27 种评测组合。训练也可选择 S/M/L 的任务分布。
6. **模糊的模型回退与结果命名。** 不再在模型缺失时自动挑选另一个目录。评测任务与模型训练任务分别由 `--task` 和 `--train-task` 指定。统一启发式结果名，并修复个别场景文件名的 `Tight1.csv` 笔误；CSV 中的种子数量按实际运行数命名。

## 新旧实验如何对照

配置修正会改变实际工作负载、截止期或训练环境；受影响场景的新旧结果不能直接视为同一实验。历史权重与 Excel 汇总表不会因代码整理而自动变成“修正后的实验”。需要报告新配置下结果时，应按同一版本重新训练、评测并出图。

跨任务规模评测仍默认使用 S 任务训练的模型，与此前泛化评测设计一致。若以 M 或 L 任务重新训练，请评测时相应指定 `--train-task M` 或 `--train-task L`。资源规模仍应匹配被加载模型的网络结构。

本次实际验证包括所有 216 个学习算法训练配置和 243 个评测配置的输入检查、九种算法 SS/Tight 单回合评测、MAHDRL 的 M/M/Medium 命令行评测、MAHDRL 与修正后 MARL L/Medium 的各一回合训练，以及一个种子的缓存生成。训练测试使用独立 `dedup_smoke_` 输出目录，没有覆盖已有模型。完整训练和全部场景的多种子实验未重跑。
